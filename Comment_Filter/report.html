🛡 2. Tầng 1 — Layer 1 Filter (Lọc cứng)

Layer 1 là tầng xử lý đầu tiên, thực hiện các phép biến đổi và kiểm tra hard-coded (không dùng ML) trên văn bản thô. Mục đích là loại bỏ nội dung độc hại, chuẩn hóa đầu vào, và giảm tải cho tầng ML.

2.1. Unicode Normalization

Tiếng Việt có nhiều cách mã hóa ký tự khác nhau (VNI, TCVN3, Unicode dựng sẵn). Nếu không chuẩn hóa, cùng một từ ở các bảng mã khác nhau sẽ được coi là khác nhau hoàn toàn.

# Python: unicodedata.normalize("NFC", text) # NFC = Canonical Decomposition, followed by Canonical Composition # Chuyển đổi: đ + í + t (combining) → địt (composed) text = unicodedata.normalize("NFC", text) # Loại bỏ ký tự null bytes text = text.replace("\x00", "").strip()
Chuẩn hóa NFC (Normalization Form C) đảm bảo rằng hai chuỗi biểu diễn cùng một ký tự nhưng ở dạng mã hóa khác nhau sẽ được chuyển về dạng nhị phân giống nhau. Ví dụ: ký tự đ có thể được mã hóa bằng một điểm mã U+0111 (composed) hoặc hai điểm mã U+0064 + U+0309 (decomposed) — NFC đưa cả hai về dạng composed.

2.2. Spam & Link Detection (Biểu thức chính quy)

Hệ thống sử dụng Regular Expression (Regex) để phát hiện nhanh các mẫu spam phổ biến trong bình luận. Regex được compile thành một automaton có độ phức tạp tuyến tính O(n) với n là độ dài chuỗi đầu vào.

STT Mẫu Regex Ý nghĩa Ví dụ
1 (.)\1{5,} Ký tự lặp 6+ lần haaaaahaha
2 [A-Z]{8,} Viết hoa dài liên tiếp AAAAAAAA
3 https?://\S+ URL HTTP/HTTPS https://bit.ly/abc
4 free.*(link|code) Quảng cáo, spam click free link now!!!
5 (casino|gambling|betting) Nội dung cờ bạc casino win free money
6 [!@#$%^&*]{5,} Ký tự đặc biệt lặp !!!!!!????
7 ^\s*[^\w]\s*$ Chỉ có ký tự đặc biệt @#$%^&*
Độ phức tạp: Regex engine trong Python (re) compile pattern vào DFA/NFA automaton. Mỗi lần gọi search() tốn O(n × m) với n = len(text), m = số pattern. Để tối ưu, toán tử | (alternation) nối tất cả pattern thành một regex duy nhất, engine chỉ duyệt chuỗi một lần O(n × k) trong đó k là hằng số engine-specific.

2.3. Profanity Detection — Levenshtein Distance

Đây là phần quan trọng nhất của Layer 1. Hệ thống phát hiện từ tục bằng hai cơ chế kết hợp:

  1. Exact Match: tra cứu O(1) trong hash table _VARIANT_TO_BASE
  2. Fuzzy Match: dùng Levenshtein Distance để phát hiện từ tục bị gõ sai chính tả, thay số thường (0→o, 1→i), hoặc chèn ký tự đặc biệt

2.3.1. Bảng từ tục cơ sở

Hệ thống định nghĩa 20 base words, mỗi base có nhiều biến thể (variants). Tổng cộng: hơn 150+ variants được index vào hash table.

2.3.2. Levenshtein Distance — Lý thuyết

Levenshtein Distance (hay Edit Distance) giữa hai chuỗi s1 và s2 là số phép biến đổi tối thiểu để biến s1 thành s2, với ba phép biến đổi: Insert (chèn), Delete (xóa), và Substitute (thay thế) — mỗi phép đều có cost = 1.

D(i, j) = min[ D(i-1, j) + 1, D(i, j-1) + 1, D(i-1, j-1) + cost(sub) ]
D(i, j) = edit distance giữa prefix s1[0..i] và s2[0..j]
Base case: D(0, j) = j (j phép insert), D(i, 0) = i (i phép delete)

Thuật toán sử dụng Dynamic Programming với bảng DP kích thước (|s1|+1) × (|s2|+1). Độ phức tạp: O(m × n) với m, n là độ dài hai chuỗi.

# Pseudocode Levenshtein Distance def levenshtein(s1, s2): if len(s1) < len(s2): s1, s2 = s2, s1 # swap để s2 luôn ngắn hơn prev = [0, 1, 2, ... , len(s2)] # hàng trên curr = [0] * (len(s2) + 1) # hàng dưới for i in range(1, len(s1) + 1): curr[0] = i for j in range(1, len(s2) + 1): cost = 0 if s1[i-1] == s2[j-1] else 1 curr[j] = min( prev[j + 1] + 1, # insert curr[j - 1] + 1, # delete prev[j] + cost # substitute ) prev, curr = curr, prev return prev[len(s2)]

2.3.3. Fuzzy Match trong hệ thống

# Threshold = 15% độ dài từ gốc THRESHOLD_RATIO = 0.15 # Với mỗi token trong comment: def _find_profanity_in_word(word): w = word.lower() results = [] for variant, length in _VARIANT_LENGTHS.items(): max_dist = max(1, int(length * THRESHOLD_RATIO)) dist = levenshtein(w, variant) if dist <= max_dist: base = _VARIANT_TO_BASE[variant] level = _BASE_TO_LEVEL[base] results.append((base, level, dist)) # Chọn kết quả tốt nhất: ưu tiên level cao & distance thấp results.sort(key=lambda x: (x[1], x[2])) # level DESC, dist ASC return [results[0]] if results else []
Ví dụ minh họa:
Input: "đjt phim gì vậy"
Token "đjt": so sánh với tất cả 150+ variants trong bảng.
levenshtein("đjt", "địt") = 1 (thiếu dấu sắc) → max_dist = max(1, 3×0.15) = max(1, 0) = 1 → khớp.
Kết quả: base="địt", censored = "****".

2.3.4. Cơ chế loại trừ word-boundary

Regex sử dụng negative lookbehind (?<!...) và negative lookahead (?!...) để đảm bảo từ tục không bị phát hiện nhầm trong các từ tiếng Việt hợp lệ. Ví dụ: từ "mbuồi" (buồi ghép với m) không được censor, nhưng "buồi" đứng riêng thì được.

# Boundary-aware pattern cho từ "địt": pattern = ( r"(?<![aăâáắấàảãạằầấẩẫậđẹêéếềểễệiíìỉĩịoôốộờớởỡợuúùủũụưứừửữựyýỳỷỹỵA-Z0-9])" r"địt" r"(?![aăâáắấàảãạằầấẩẫậđẹêéếềểễệiíìỉĩịoôốộờớởỡợuúùủũụưứừửữựyýỳỷỹỵA-Z0-9])" ) # Dịch: chữ cái/digit/Unicode tiếng Việt đứng TRƯỚC hoặc SAU không được tính là boundary

2.4. Censor & Rejection Logic

Sau khi phát hiện từ tục, hệ thống thay thế từng ký tự trong từ bằng dấu * (giữ nguyên độ dài). Logic quyết định reject:

# Censor: thay mỗi ký tự bằng "*", giữ khoảng trắng def _censor_word(word): return "".join("*" if not c.isspace() else c for c word) # Tỷ lệ từ tục = số từ tục / tổng số từ profanity_ratio = profanity_count / max(word_count, 1) # Ngưỡng reject: # REJECTED nếu: ratio >= 60% VÀ count >= 3 từ if profanity_ratio >= 0.6 and profanity_count >= 3: return Layer1Result(valid=False, reject_reason="HIGH_PROFANITY")
Ngưỡng cụ thể
profanity_ratio ≥ 0.6 (≥60% từ trong comment là tục từ)
AND profanity_count ≥ 3
→ Comment bị REJECTED ở Layer 1.
Mục đích ngưỡng kép
Ngưỡng kép ngăn chặn reject nhầm comment ngắn có 1 từ tục nhưng ratio cao.
Đảm bảo comment như "buồi ghê" (2 từ, 1 tục → 50%) vẫn có thể được APPROVED.

🤖 3. Tầng 2 — Sentiment Classification

Tầng 2 sử dụng Machine Learning để phân loại cảm xúc. Mô hình là pipeline kết hợp TF-IDF Vectorizer (trích xuất đặc trưng) và Logistic Regression (bộ phân loại đa lớp).

3.1. TF-IDF Vectorizer

TF-IDF (Term Frequency – Inverse Document Frequency) là phương pháp chuyển văn bản thành vector số thực, phản ánh tầm quan trọng của mỗi từ trong corpus.

TF-IDF(t, d) = TF(t, d) × IDF(t)
TF(t, d) = số lần từ t xuất hiện trong document d
IDF(t) = log(N / df(t)) với N = tổng docs, df(t) = số docs chứa t

Các tham số TF-IDF trong model:

Tham sốGiá trịÝ nghĩa
max_features15.000Số chiều vector tối đa (lấy top-15K từ có IDF cao nhất)
ngram_range(1, 3)Unigram + Bigram + Trigram — giữ được cụm từ như "rất hay", "diễn xuất tuyệt vời"
min_df2Bỏ qua từ xuất hiện ít hơn 2 lần trong corpus (loại noise)
max_df0.95Bỏ qua từ xuất hiện trong ≥95% docs (loại stopwords)
sublinear_tfTrueDùng 1 + log(TF) thay vì TF thô — giảm ảnh hưởng từ quá phổ biến
analyzer"word"Phân tích theo từ (không phải ký tự)
Tại sao chọn TF-IDF thay vì Word2Vec / BERT?
TF-IDF là phương pháp bag-of-words đơn giản, không cần GPU, train nhanh, dễ triển khai. Với dataset 1.500 mẫu (khá nhỏ), TF-IDF + LogReg đạt accuracy >85% — phù hợp cho bài toán thực tế và môi trường production.

3.2. Logistic Regression (Đa lớp Multinomial)

Logistic Regression là bộ phân loại tuyến tính, mở rộng cho đa lớp bằng chiến lược One-vs-Rest (OvR) hoặc Multinomial (softmax). Trong model này dùng Multinomial.

P(y=k | x) = exp(wkT x + bk) / Σj exp(wjT x + bj)
Softmax biến đổi raw scores (logits) thành xác suất.
Cross-Entropy Loss: L = −Σ yi log(ŷi).
Tham sốGiá trịGiải thích
C1.0Inverse of regularization strength — C nhỏ → regularization mạnh → giảm overfitting
max_iter1000Số lần lặp tối đa của thuật toán tối ưu
solverlbfgsThuật toán tối ưu hóa cho Logistic Regression đa lớp
multi_classmultinomialDùng softmax thay vì OvR — chính xác hơn cho nhiều lớp
class_weightbalancedTự động cân bằng trọng số class — bù cho imbalance dataset
n_jobs-1Dùng tất cả CPU cores để train song song

3.2.1. Class Weight Balancing

Tham số class_weight="balanced" tự động tính trọng số cho mỗi lớp theo công thức:

wk = N / (K × nk)
N = tổng số mẫu, K = số lớp (3), nk = số mẫu thuộc lớp k.
Ví dụ: N=1500, POSITIVE=500 → w=1500/(3×500)=1.0; SPOILER=500 → w=1.0
→ Mọi lớp có trọng số bằng nhau (dataset đã balanced 500/500/500).

3.3. Spoiler Detection (Kết hợp ML + Keyword)

Spoiler Detection sử dụng cơ chế Hybrid: kết hợp xác suất từ Logistic Regression (Layer 2 ML) với tra cứu keyword cứng.

# Bảng spoiler keywords tiếng Việt (40+ từ khóa) _SPOILER_KEYWORDS = [ "spoiler", "tiết lộ", "twist", "sốc", "twist cuối", "nhân vật chính thực ra", "phát hiện ra", "đừng đọc", "chết ở", "tự tử", "hy sinh", ... ] # Đếm số keywords khớp → confidence def _contains_spoiler_keywords(text): text_lower = text.lower() match_count = sum(1 for kw in SPOILER_KEYWORDS if kw in text_lower) confidence = min(match_count * 0.3, 0.95) has_spoiler = (match_count >= 2) or (confidence >= 0.5) return has_spoiler, round(confidence, 4)

3.3.1. Công thức quyết định Spoiler cuối cùng

# Gộp confidence từ ML (Layer 2) + Keyword Detection ml_spoiler_conf = sentiment_probs["SPOILER"] # xác suất từ Logistic Regression keyword_spoiler, keyword_conf = _contains_spoiler_keywords(text) # Quyết định cuối cùng: if ml_spoiler_conf >= 0.5 or keyword_spoiler: spoiler = True spoiler_conf = max(ml_spoiler_conf, keyword_conf, 0.5) else: spoiler = False spoiler_conf = round(min(ml_spoiler_conf, 0.3), 4) # Boost nếu ML đã classify là SPOILER if sentiment_label == "SPOILER": spoiler_conf = max(spoiler_conf, 0.6)

Lưu ý: Dataset sau mở rộng không còn balanced 500/500/500 hoàn toàn. Tham số class_weight="balanced" trong Logistic Regression tự động bù trừ bằng trọng số:
w_k = N / (K × n_k)
Ví dụ: POSITIVE w = 1880/(3×638) ≈ 0.98 · NEGATIVE w = 1880/(3×702) ≈ 0.89 · SPOILER w = 1880/(3×540) ≈ 1.16

5.2. Các chỉ số đánh giá

Accuracy
Tỷ lệ dự đoán đúng trên tổng số mẫu:
Accuracy = (TP + TN) / Total
Precision / Recall / F1
Precision = TP / (TP + FP) — độ chính xác
Recall = TP / (TP + FN) — bao phủ
F1 = 2 × P × R / (P + R)

8.2.2. SVM + Character N-gram (không cần GPU)

  • Ước tính accuracy cải thiện +2–4%
# Upgrade 1: SVM + char n-gram (khong can GPU) from sklearn.svm import LinearSVC from sklearn.pipeline import Pipeline pipeline = Pipeline([ ("tfidf", TfidfVectorizer( analyzer="char_wb", # character n-gram, word boundary ngram_range=(3, 5), max_features=20_000, sublinear_tf=True, )), ("clf", LinearSVC( C=1.0, class_weight="balanced", max_iter=5000, )), ])

8.3. Phase 2 — PhoBERT Fine-tune (Tuần 3–6)

PhoBERT là pre-trained BERT cho tiếng Việt, fine-tune trên dataset riêng để phân loại sentiment. Đây là phương pháp tối ưu nhất cho bài toán này — vừa đủ nhẹ để chạy inference real-time, vừa hiểu ngữ cảnh sâu.

Tại sao PhoBERT?
  • Pre-trained trên 20GB Vietnamese text (Wikipedia, news)
  • Hiểu ngữ cảnh hai chiều — phủ định, sarcasm đều xử lý được
  • Fine-tune chỉ cần 2.000–5.000 mẫu là đủ
  • Model nhẹ: ~420MB, inference ~50ms trên CPU
  • Cộng đồng Vietnamese NLP mạnh, có sẵn weights
Cách Fine-tune
  • Load: vinai/phobert-base (HuggingFace)
  • Thêm classification head (linear)
  • Train: 5 epochs, lr=2e-5, batch=16
  • Validation: 10% hold-out, early stopping
  • Export: ONNX runtime → inference nhanh gấp 3 lần
# Phase 2: Fine-tune PhoBERT (Python) # pip install transformers torch from transformers import AutoTokenizer, AutoModelForSequenceClassification, Trainer model_name = "vinai/phobert-base" tokenizer = AutoTokenizer.from_pretrained(model_name) model = AutoModelForSequenceClassification.from_pretrained( model_name, num_labels=3 ) # Encode dataset def tokenize(batch): return tokenizer(batch["text"], padding=True, truncation=True, max_length=128) # Fine-tune 5 epochs, lr=2e-5 # Expected accuracy: 91-95% vs 82-87% cua TF-IDF + LogReg # Expected improvement on sarcasm: from ~30% → ~85% correct

8.4. Phase 3 — Sarcasm Detection Module (Tuần 7–10)

Module riêng cho Sarcasm & Irony
Ngay cả PhoBERT cũng chưa xử lý sarcasm tốt 100% — cần một module riêng:
  • Sentiment Contrast Detection: so sánh sentiment tích cực với hành động tiêu cực ("hay quá" + "ngủ quên") → flag sarcasm
  • Contextual Embedding: dùng sentence-transformers (sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) để encode câu → cosine similarity với sarcasm template embeddings
  • Rule-based trigger: các pattern như "hay quá" + verb tiêu cực, "tuyệt vời" + emoji-negative
  • Output: binary sarcasm score → nhân với sentiment confidence → điều chỉnh nhãn
